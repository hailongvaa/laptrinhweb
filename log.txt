1. FILE: mai/bang1.sql (Khởi tạo CSDL & Thiết kế 4 Bảng - DDL)
   * Xây dựng CSDL hoàn chỉnh gồm 4 bảng:
     - customers: id, full_name, email (UNIQUE), phone (UNIQUE), address, created_at.
     - products: id, product_code (UNIQUE), name, scale (tỉ lệ), manufacturer,
       car_brand, price, stock_quantity, status (CHECK in_stock/pre_order/out_of_stock), created_at.
     - orders: id, order_code, customer_id (Khóa ngoại FK nối customers.id),
       recipient_name, recipient_phone, shipping_address, total_amount,
       order_status (CHECK pending/confirmed/shipping/delivered/cancelled), created_at.
     - order_items: id, order_id (FK nối orders.id ON DELETE CASCADE),
       product_id (FK nối products.id), quantity (CHECK > 0), unit_price.

2. FILE: mai/bang2.sql (Nạp dữ liệu mẫu - DML / Mock Data)
   * Nạp sẵn bộ dữ liệu mẫu thực tế:

     - 4 mô hình xe thật thuộc các hãng AutoArt, Bburago, Tomica với tỉ lệ 1:18, 1:24, 1:64
       (Porsche 911 GT3 RS, Lamborghini Aventador SVJ, Honda Civic Type R FL5, Mercedes-AMG G63).
     - 1 đơn hàng mẫu (ORD-2026-0001) và 2 chi tiết đơn hàng (mua Porsche + Lamborghini).

3. FILE: mai/bang3.sql (Truy vấn kiểm tra & Báo cáo - DQL)
   * Các câu lệnh SELECT tra cứu từng bảng.
   * Câu lệnh JOIN 4 bảng kết nối orders + customers + order_items + products để
     trích xuất toàn bộ thông tin chi tiết một đơn đặt hàng.

   - Bạn Mai (tmai) nộp bổ sung file truy vấn kiểm tra dữ liệu "bang data.sql" 
     (tương ứng "plan/bang dattamai.sql") với mục tiêu kiểm tra dữ liệu các bảng 
     đã tạo của hệ thống: users, brands, products, accessories.
   - Đồng thời bạn Mai cung cấp các file API Client ("plan/api.js", "plan/config.js", 
     "plan/main.js") gọi đến các endpoint GET /api/products, POST /api/contact.
2. Vấn đề phát sinh khi đối soát với hệ thống cũ:
   - Tên cơ sở dữ liệu bị lệch: File của Mai dùng "USE CarModelStoreDB;", trong khi 
     backend cũ đang kết nối "car_order_db" (hoặc "diecast_car_shop").
   - Lệch cấu trúc bảng: File của Mai truy vấn 4 bảng (users, brands, products, accessories),
     nhưng trong CSDL cũ chỉ có 4 bảng (customers, products, orders, order_items), 
     thiếu bảng brands, accessories và thiếu 2 bảng đơn hàng trong file truy vấn của Mai.
   - Khi chạy "bang data.sql" trên SQL Server sẽ gặp lỗi "Invalid object name".

II. CÁC THAY ĐỔI ĐÃ THỰC HIỆN ĐỂ ĐỒNG BỘ TOÀN DIỆN (THEO TMAI):

1. Chuẩn hóa Cơ sở dữ liệu CarModelStoreDB:
   - Thống nhất tên CSDL chính thức của đề tài là: "CarModelStoreDB".
   - Nâng cấp kịch bản "database/00_full_setup.sql" để tự động khởi tạo CSDL 
     CarModelStoreDB, đồng thời hỗ trợ dự phòng linh hoạt với "car_order_db".

2. Mở rộng và chuẩn hóa hệ thống 6 Bảng quan hệ chuẩn 3NF:
   - Bảng users: Lưu tài khoản Người dùng & Quản trị viên (id, username, password, 
     full_name, email, phone, address, role, created_at) phục vụ login.html và register.html.
   - Khởi tạo VIEW customers: Ánh xạ từ bảng users để tương thích ngược 100% với 
     mọi mã nguồn và câu lệnh cũ dùng customers.
   - Bảng brands: Lưu danh mục 9 thương hiệu xe đối tác (Ferrari, Lamborghini, Porsche, 
     Mercedes-Benz, BMW, Nissan, Honda, Ford, Toyota) phục vụ brands.html & brand-detail.html.
   - Bảng products: Lưu 6 mô hình xe hoàn chỉnh kèm brand_id (khóa ngoại nối brands), 
     mã SKU, tỉ lệ, hãng sản xuất, giá bán, tồn kho, trạng thái (in_stock, pre_order, 
     out_of_stock, bestseller), link ảnh Unsplash, đánh giá sao phục vụ products.html.
   - Bảng accessories: Lưu 4 phụ kiện trưng bày (Hộp Mica, Đế xoay 360, Bộ vệ sinh, 
     Garage diorama LED) phục vụ accessories.html.
   - Bảng orders: Lưu đơn hàng nhận từ giỏ hàng (cart.html) và hiển thị trên admin/orders.html.
   - Bảng order_items: Lưu chi tiết sản phẩm trong từng đơn (khóa ngoại nối orders & products).

3. Cập nhật và hoàn thiện file "database/bang data.sql":
   - Tự động nhận diện CSDL: Tự động kiểm tra và ưu tiên "CarModelStoreDB", chuyển an toàn 
     sang "car_order_db" nếu cần.
   - Truy vấn đầy đủ toàn bộ 6 bảng của hệ thống:
     + SELECT * FROM users;          (Danh sách tài khoản & khách hàng)
     + SELECT * FROM brands;         (Danh sách thương hiệu xe)
     + SELECT * FROM products;       (Danh sách mô hình xe)
     + SELECT * FROM accessories;    (Danh sách phụ kiện trưng bày)
     + SELECT * FROM orders;         (Danh sách đơn đặt hàng)
     + SELECT * FROM order_items;    (Danh sách chi tiết đơn hàng)
   - Bổ sung câu lệnh JOIN báo cáo toàn diện: Kết nối Khách hàng + Đơn hàng + Sản phẩm 
     để kiểm tra dòng chảy dữ liệu thực tế.
   - Đồng bộ hóa tương tự cho các file "database/01_create_tables.sql", 
     "database/02_insert_mock_data.sql", "database/03_queries_and_reports.sql" 
     và "plan/bang dattamai.sql".

4. Nâng cấp Máy chủ Backend Node.js ("car-store-backend/server.js"):
   - Cấu hình Connection Pool đa tầng: Tự động ưu tiên kết nối tới "CarModelStoreDB", 
     nếu chưa có sẽ tự động dự phòng kết nối sang "car_order_db".
   - Bổ sung các API RESTful phục vụ kết nối động theo code của Mai:
     + GET /api/products: Lấy danh sách mô hình xe từ CSDL (hỗ trợ lọc theo query ?status=...).
     + GET /api/brands: Lấy danh sách thương hiệu xe từ CSDL.
     + GET /api/accessories: Lấy danh sách phụ kiện từ CSDL.
     + POST /api/contact: Tiếp nhận dữ liệu form liên hệ từ contact.html.
   - Giữ nguyên vẹn 100% các API cốt lõi hiện có: GET /api/health, GET /api/orders, 
     POST /api/orders.
